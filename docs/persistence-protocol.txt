DSH 插件持久化协议（草案 v1）
================================

适用范围
  所有需要在插件重启 / 面板收起重开后保留的数据：UI 偏好、分支筛选、
  reflog 快照，以及以后新增的任何插件状态。

存储位置
  插件安装根目录下的 `.data/state.json`。
  - 安装根 = 实际加载的插件目录（profile 的 node_modules 或 _stage）。
  - 不写工作区、不写仓库、不写浏览器 localStorage。
  - 卸载插件时目录一起删除，不留残留。
  - 部署链路 工作区 → _stage → profile 用 robocopy /E，不会删除目标里
    已有的 `.data`；只有卸载 / 整目录删除才会清空。

文件格式
  {
    "<key>": <任意 JSON 值>,
    ...
  }
  单文件键值存储；写入用「临时文件 + rename」保证原子性；写操作在 host
  侧串行排队，避免并发读改写互相覆盖。

键命名约定
  <domain>:<repoRoot>         按仓库分键，root 用 snapshot.root（不用 cwd）
  branch-filter:<root>        分支筛选数组，空数组表示「全选」
  reflog:<root>               持久化的 reflog 事件快照
  reflog-backup:<root>        reflog 备份开关（布尔，默认 false）
  ui:modal-anchor             弹窗位置："panel"（默认）| "screen"
  新数据一律按 <domain>:<repoRoot> 追加，不把无关数据塞进同一个键。

接口
  Host 半（GitGateway）：
    readPluginState({ key })                 -> { ok, value }   value 为 JSON 文本
    writePluginState({ key, value })         -> { ok }          value 为 JSON 文本
    reflogBackup({ path })                   -> { ok, added, total }
    reflogBackupRead({ path })               -> { ok, events }
    reflogBackupConfig({ path, enabled? })   -> { ok, enabled, total }

  Browser 半：统一经 ctx.remote.git 调用，请求走 typert 严格 schema；
  新增方法要同时在 typert.host.js 与 remote 包的 descriptor 里登记。

实现要点
  - lib/state.mjs 负责文件读写，PLUGIN_ROOT 由 import.meta.url 推导。
  - 读取缺失键返回字符串 "null"；非法 JSON 的写请求直接拒绝，旧值保留。
  - 写入失败不得影响面板主流程（调用方 catch 后静默）。
  - 测试用 DSH_GIT_STATE_DIR 指向临时目录，避免测试数据写进插件目录。

新增持久化内容的步骤
  1. 在 AGENTS.md 的持久化键表登记键名与结构。
  2. 需要新语义时新增 host 方法，并同步 typert.host.js 与 remote descriptor。
  3. 客户端只通过 ctx.remote.git 读写，不直接碰文件系统。
  4. 补 test-host 的 round-trip 与 test-client-offline 的恢复用例。
